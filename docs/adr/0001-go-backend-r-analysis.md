# 0001. Go для сервера, R для статистики

- **Статус:** Принято
- **Дата:** 2026-10-24

## Контекст

Нужны веб-интерфейс, загрузка данных из внешнего API и статистический анализ (непараметрические тесты трендов, кластеризация, PCA, корреляции). Статистические методы должны быть прозрачными и проверяемыми.

## Решение

- HTTP-сервер, загрузка данных и кэширование — на Go (только стандартная библиотека).
- Вся статистика — на R; Go запускает `Rscript analysis/run.R <метод>` на каждый некэшированный запрос, передаёт JSON в stdin и читает JSON из stdout.
- Тесты Манна–Кендалла и Тейла–Сена реализованы вручную в базовом R и проверены тестами, а не взяты из пакетов `trend`/`Kendall`.

## Последствия

- R-код можно запускать и отлаживать отдельно от сервера, передав JSON вручную.
- Граница между компонентами — простой JSON-контракт, без сетевых протоколов и привязок к языкам.
- Каждый холодный запрос платит за старт процесса R (~0,3 с) и чтение CSV; это компенсируется кэшем.
- Минимум зависимостей: один R-пакет (`jsonlite`), ноль Go-модулей.
- Параллельные холодные запросы порождают несколько процессов R; при многопользовательской нагрузке это потребовало бы пула воркеров.

## Рассмотренные альтернативы

- **Plumber (R как HTTP-сервис)** — отдельный долгоживущий процесс без старта на каждый запрос, но лишний сервис и пакет-зависимость.
- **Shiny** — быстрее для прототипа, но хуже контроль над API и интерфейсом.
- **Всё на Python** — возможно, но статистическая часть курса ориентирована на R.
