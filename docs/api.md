# HTTP API

Базовый адрес: `http://localhost:8080`. Все ответы — JSON в UTF-8. Аутентификации нет: сервис рассчитан на локальный запуск.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/locations` | Список точек и состояние их данных |
| `POST` | `/api/fetch` | Запустить загрузку данных из Open-Meteo |
| `GET` | `/api/status` | Ход фоновой загрузки |
| `GET` | `/api/analysis/{method}` | Результат метода анализа |
| `GET` | `/*` | Статика фронтенда (неизвестные пути → `index.html`) |

## Ошибки

Ошибка всегда имеет вид:

```json
{ "error": "описание на русском" }
```

| Код | Когда |
|---|---|
| `400` | Неизвестная точка, недопустимый `var` или `k`, некорректное тело запроса |
| `404` | Неизвестный метод анализа |
| `409` | Загрузка уже выполняется |
| `412` | Данные не загружены (вообще или для запрошенной точки) |
| `500` | Ошибка или таймаут R-скрипта |

## `GET /api/locations`

Возвращает все точки из `data/locations.json`. Поле `data` равно `null`, если CSV для точки нет.

```json
[
  {
    "id": "minsk", "name": "Минск", "zone": "Умеренный континентальный",
    "lat": 53.9, "lon": 27.57,
    "data": {
      "rows": 27394, "from": "1950-01-01", "to": "2024-12-31",
      "missing": 0, "complete": 100, "modTime": 1732400000
    }
  }
]
```

| Поле `data` | Описание |
|---|---|
| `rows` | Число суток в ряде |
| `from`, `to` | Первая и последняя дата |
| `missing` | Число пустых ячеек по всем параметрам |
| `complete` | Доля заполненных ячеек, % |
| `modTime` | Время изменения файла (Unix, с) |

## `POST /api/fetch`

Запускает фоновую загрузку и сразу возвращает `202 Accepted`.

Тело (необязательно):

```json
{ "ids": ["minsk", "yakutsk"] }
```

Без тела или с пустым `ids` загружаются все точки. Существующие файлы перезаписываются.

Ответ: `{ "total": 2 }`

```bash
curl -X POST localhost:8080/api/fetch -H 'Content-Type: application/json' -d '{"ids":["minsk"]}'
```

## `GET /api/status`

```json
{ "running": true, "done": 3, "total": 10, "errors": { "lapaz": "open-meteo: HTTP 429" } }
```

До первой загрузки после старта сервера возвращает нулевые значения (`errors: null`).

## `GET /api/analysis/{method}`

Параметры, не перечисленные для метода, игнорируются.

| `method` | Параметры | Описание |
|---|---|---|
| `seasonality` | `loc` (обяз.) | Месячные нормы, амплитуда, годовые аномалии |
| `compare` | `k` (2–8, по умолч. 4) | Показатели всех точек, k-means, PCA |
| `trends` | `loc`, `var` | Без `loc` — рейтинг точек по скорости тренда; с `loc` — подробно по годам и сезонам |
| `extremes` | `loc` (обяз.) | Пороги, годовые счётчики экстремумов, их тренды, рекорды |
| `correlations` | `loc` (обяз.) | Матрицы Пирсона и Спирмена, выборка 900 суток для scatter |
| `insights` | — | Помесячные прикладные индексы для всех точек |
| `quality` | — | Пропуски, выбросы, интерполяция по каждому параметру (в UI не используется) |

`var` ∈ `tmean`, `tmax`, `tmin`, `precip`, `wind`; по умолчанию `tmean`.

Методы, работающие «по всем точкам» (`compare`, `trends` без `loc`, `insights`, `quality`), используют только точки с загруженными данными.

### Пример: `trends` по одной точке

```bash
curl 'localhost:8080/api/analysis/trends?loc=minsk&var=tmean'
```

```json
{
  "location": { "id": "minsk", "name": "Минск", "zone": "...", "lat": 53.9, "lon": 27.57 },
  "var": "tmean", "unit": "°C", "per": "десятилетие",
  "years": [1950, 1951, "..."], "values": [5.1, 6.3, "..."],
  "stats": {
    "n": 75, "mk_tau": 0.41, "mk_z": 5.2, "mk_p": 0,
    "sen": 0.31, "sen_lo": 0.24, "sen_hi": 0.38, "sen_intercept": -54.2,
    "ols": 0.32, "ols_lo": 0.24, "ols_hi": 0.4, "ols_p": 0, "r2": 0.35,
    "significant": true, "direction": "рост"
  },
  "sen_line": { "x": [1950, 2024], "y": [5.6, 7.9] },
  "seasons": [ { "season": "DJF", "label": "Зима (дек–фев)", "n": 74, "sen": 0.45, "...": "..." } ]
}
```

Значения в примере иллюстративные. Скорости трендов (`sen`, `ols` и их ДИ) приведены к единицам **за десятилетие**; `sen_intercept` — в единицах за год (для построения линии).

### Пример: `compare`

```json
{
  "base": "1991–2020", "months": ["Янв", "..."], "k": 4,
  "features": ["tmean", "amplitude", "precip_year", "wind", "hum", "hot_days", "frost_days", "heavy_rain_days"],
  "table": [ { "id": "minsk", "name": "Минск", "tmean": 7.1, "cluster": 2, "pc1": -0.8, "pc2": 1.2, "...": "..." } ],
  "profiles": [ { "id": "minsk", "tmean": [-4.5, "..."], "precip": [38, "..."] } ]
}
```

Полный набор полей каждого метода — в соответствующей функции `m_*` в [`analysis/methods.R`](../analysis/methods.R). Пропущенные значения сериализуются как `null`, числа округляются до 4 значащих цифр.
